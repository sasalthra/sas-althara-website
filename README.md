# ساس الثراء — الموقع ولوحة الإدارة

نسخة المصدر للتعديل في VS Code. هذه حزمة تطوير وليست ملفات جاهزة للاستبدال داخل public_html.

## تشغيل نسخة محلية

ثبّت Node.js 22.13 أو أحدث وGit وVS Code، ثم افتح مجلد المشروع في VS Code وشغّل:

```sh
npm ci
npm run dev
```

افتح http://localhost:5173. لإجراء فحص البناء:

```sh
npm run build
node scripts/check-crm.mjs
```

الدخول المحلي للإدارة معطّل عمدًا. اختبار الإدارة يستخدم قاعدة مؤقتة وهوية محاكاة، ولا يثبت تسجيل الدخول الحقيقي.

## ملفات التعديل

- app/page.tsx: أقسام الرئيسية.
- app/site-header.tsx: الشعار والتنقل.
- app/sas-brand.css وapp/site.css: الألوان والتنسيق.
- app/catalog.tsx: قائمة العقارات والبحث.
- app/properties/[id]/page.tsx: تفاصيل العقار.
- app/crm/: واجهة الإدارة.
- app/api/leads/route.ts: قراءة العملاء وإضافتهم وتحديثهم.
- data/properties.json: بيانات 87 عقارًا؛ ليست قاعدة عملاء حية.
- public/brand وpublic/media: أصول الموقع والصور.
- db/ وdrizzle/: نموذج قاعدة البيانات وترحيل مخططها.

## رفع المصدر إلى GitHub

أنشئ مستودعًا خاصًا فارغًا في حسابك. من Source Control في VS Code اختر Initialize Repository، ثم احفظ أول commit، ثم Publish to GitHub واختر Private. إذا كان المستودع موجودًا بالفعل، استخدم رابطه الصحيح ولا تكتب فوق محتوياته.

لا ترفع node_modules أو ملفات البيئة أو قواعد العملاء أو نسخ WordPress/SQL الأصلية. الملف .gitignore يستبعد الملفات المحلية المعتادة. الحزمة لا تحتوي تاريخ Git أو بيانات عملاء CRM الحية أو أسرار الاستضافة.

## ما يلزم قبل استبدال الموقع الحالي

التطبيق يستخدم Vinext/React وCloudflare Workers/D1 وخدمة هوية منصة Sites. ليس موقع PHP أو تصدير HTML ثابتًا. وجود حزمة next لا يعني أنه جاهز للنشر بتعليمات Next.js المعتادة.

1. تحديد باقة الاستضافة وقدراتها أو اختيار استضافة تطبيق مناسبة.
2. إعداد قاعدة بيانات مستقلة وترحيل مخططها، ونقل العملاء الحيين إن وجدوا بصورة منفصلة وخاصة.
3. استبدال اعتماد app/chatgpt-auth.ts على ترويسات منصة Sites بتسجيل دخول موثوق بجلسات موثقة، وتقييد الإدارة بالبريد sasalthra.sa@gmail.com. لا تثق بترويسات oai-authenticated-user-* على خادم خارجي؛ يستطيع العميل إرسالها ما لم تتحقق بوابة موثوقة منها. لا تنشر واجهات الإدارة بهذه الآلية خارج Sites.
4. تفعيل MFA لدى مزود الهوية واختبار الدخول المعتمد ورفض الآخرين والجلسات وتسجيل الخروج.
5. اختبار نسخة مرحلية: الروابط والصور والنماذج وحفظ العملاء والصلاحيات والجوال.
6. أخذ نسخة احتياطية من الموقع وقاعدة WordPress وإعدادات DNS، وإعداد تحويلات روابط العقارات القديمة وحماية سجلات بريد الدومين.
7. بعد نجاح الاختبارات، تحويل الدومين إلى النسخة الجديدة مع الاحتفاظ بالقديمة للرجوع عند الحاجة.

صفحات الأخبار وحاسبة التمويل وبعض روابط التواصل ما زالت تشير للموقع القديم. يجب نقلها أو إبقاء وجهاتها عاملة قبل تحويل الدومين. الحزمة لا تشمل تفريغ WordPress الأصلي أو الموقع القديم الكامل.

## حدود النسخة

87 عقارًا في المعاينة و30 سجلًا معلّقًا في مخرجات التدقيق المنفصلة. لوحة العقارات للعرض، والعملاء يدعمون الإضافة والتحديث والمتابعة. المصادقة الثنائية لم تُفعّل. .openai/hosting.json يصف معاينة Sites الحالية، وليس إعداد استضافتك الخارجية.
